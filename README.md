## Подготовка данных

Временное разбиение: train до 2021-07-01, validation с 2021-07-01 до 2021-08-01, test с 2021-08-01. Для первого эксперимента выбираются 10 000 пользователей, имеющих взаимодействия минимум в три разных дня train. Выбор пользователей и словарь объектов используют только train.

Цель reward model — `watched_pct / 100`. Пропуски reward не заменяются нулями.

Даты имеют точность до дня. Контекст каждого целевого взаимодействия содержит только события предыдущих дней, максимум 64 объекта. Внутри уже прошедшего дня объекты упорядочены по ID: это приближение, а не наблюдаемый порядок просмотров.

В validation/test история обновляется ранее наблюдавшимися событиями, веса модели остаются фиксированными. Объекты вне train-словаря исключаются из целей с учётом числа исключений в аудите. Оценка на этой подвыборке относится к активным warm-пользователям и известным объектам, а не ко всей аудитории KION.

Подготовку данных можно запустить отдельно:

```bash
python3 scripts/prepare_data.py
```

## GPT-2 baseline на MPS

GPT-2 обучается с нуля на ID объектов, выходная голова связана с эмбеддингами. Используются два слоя, размерность 64 и две головы внимания. Loss считается только для цели после всей истории, с исключением padding из распределения рекомендаций.

Отдельный запуск исходного baseline на 10k пользователей:

```bash
python3 scripts/train_baseline.py --device mps
```


Обучение — до 8 эпох с early stopping после двух эпох без улучшения validation NDCG@10. Используются MPS и float32.

Recall/NDCG вычисляются по всему train-каталогу, сначала усредняются по событиям пользователя, затем по пользователям. Повторы не маскируются. Дополнительно измеряются покрытие каталога, концентрация, энтропия, популярность и доля рекомендаций из последних 64 объектов истории. Последняя метрика не равна доле повторов за всю историю.


## Reward model 

Модель предсказывает `watched_pct / 100` по истории и кандидату. Эмбеддинги инициализируются из GPT-2 и дообучаются. История агрегируется с большим весом недавних объектов. Нейросетевая поправка добавляется к сглаженному среднему отклику объекта, вычисленному только на train; sigmoid ограничивает выход диапазоном [0, 1].

```bash
python3 scripts/train_reward.py --device mps
```

Лучшая модель выбирается по validation RMSE, обучение — до 12 эпох с early stopping. Используются только события с известным reward. Контроли: средний train-отклик и сглаженный средний отклик объекта.

Отложенная оценка относится к наблюдавшимся взаимодействиям. Она не гарантирует корректность reward для любых новых рекомендаций; отсутствующие взаимодействия не используются как отрицательные примеры. Test остаётся для финальной оценки.

## RL-дообучение на MPS

```bash
python3 scripts/train_rl.py --run-dir experiments/users50k --device mps
```

Одношаговый REINFORCE: для каждой реальной train-истории независимо с возвращением сэмплируются четыре объекта. Baseline для каждого действия — средний reward остальных трёх действий. Оптимизируется `E[R] − β KL(policy || reference)`; KL вычисляется точно по train-каталогу. Reference и reward model заморожены.

Сравниваются четыре варианта: исходный reward с β = 0.01, 0.1, 1.0 и reward со штрафом 0.2 за объект из последних 64 элементов контекста при β = 0.1. Контроль — продолжение supervised-обучения с тем же числом обновлений и learning rate. Каждый вариант стартует из одной исходной модели; 150 обновлений, оценка на шагах 75 и 150.

Помимо релевантности измеряются предсказанный reward, KL, покрытие каталога, концентрация и повторы рекомендаций. Метрики reward и KL усредняются по событиям внутри пользователя, затем по пользователям.

Внутри варианта выбирается модель с наибольшей регуляризованной Monte Carlo целью при ограничении `NDCG@10 >= 0.95 * baseline` на validation. Если подходящих моделей нет, фиксируется нарушение ограничения. Между RL-вариантами выбирается наибольший исходный reward top-10 при том же ограничении. Порог 5% задан до запуска RL; он не означает статистическую значимость.


### Результат сравнения 10k и 50k

| Метрика на фиксированной validation | 10k | 50k |
|---|---:|---:|
| GPT-2 NDCG@10 | 0.08454 | 0.08704 |
| GPT-2 Recall@10 | 0.17740 | 0.16432 |
| GPT-2 coverage@10 | 0.399% | 1.378% |
| Reward model RMSE | 0.39974 | 0.39584 |
| Reward model корреляция | 0.29946 | 0.34042 |

Увеличение выборки улучшило NDCG и покрытие, но снизило Recall@10. Для RL выбраны модели 50k по основной метрике NDCG@10 и качеству reward model. Лучшая эпоха обеих моделей — первая. Сравнение не уравнивает вычислительный бюджет: у baseline 50k одна эпоха содержит 1980 обновлений против 396 у 10k.

Reward model 50k сохраняет ограниченное качество и оптимистичное смещение: среднее предсказание 0.57229 против наблюдаемого 0.53511. Рост её оценки после RL следует анализировать как изменение proxy, вместе с релевантностью, концентрацией и поддержкой объектов в train.

## RL 50k: результаты на validation

| Вариант | NDCG@10 | Предсказанный reward@10 | KL |
|---|---:|---:|---:|
| baseline | 0.08704 | 0.5968 | 0 |
| sft_control | 0.08721 | 0.5995 | 0.0035 |
| raw_kl001 | 0.08472 | 0.6467 | 0.0865 |
| raw_kl01 | 0.08633 | 0.6409 | 0.0567 |
| raw_kl1 | 0.08662 | 0.6193 | 0.0036 |
| repeat_kl01 | 0.08651 | 0.6423 | 0.0540 |

Все выбранные модели удовлетворяют заранее заданному ограничению validation NDCG. По исходному правилу основной вариант — `raw_kl001`: reward вырос на 0.0499, NDCG снизился примерно на 2.66%. Вариант `raw_kl01` показывает более мягкий компромисс: reward вырос на 0.0441, NDCG снизился примерно на 0.81%. Выбор зафиксирован до оценки на test.

## Финальная оценка 

```bash
python3 scripts/final_evaluation.py --run-dir experiments/users50k --device mps
```

Оценка включает 2000 парных bootstrap-ресэмплирований пользователей и генерацию цепочек до пяти объектов для 256 одинаковых стартовых контекстов. Сравниваются greedy и sampling, измеряются reward, повторы и чувствительность reward model к синтетическому контексту. Интервалы учитывают вариативность пользователей при фиксированных моделях, но не вариативность обучения по seed.

| Модель | Test Recall@10 | Test NDCG@10 | Предсказанный reward@10 |
|---|---:|---:|---:|
| Популярность | 0.08611 | 0.04773 | — |
| Baseline | 0.09787 | 0.05363 | 0.6053 |
| Supervised-контроль | 0.09610 | 0.05272 | 0.6082 |
| raw_kl001 | 0.09696 | 0.05336 | 0.6544 |
| raw_kl01 | 0.09633 | 0.05342 | 0.6490 |
| raw_kl1 | 0.09853 | 0.05369 | 0.6276 |
| repeat_kl01 | 0.09636 | 0.05320 | 0.6502 |

- **Популярность** — самые популярные объекты train без персонализации.
- **Baseline** — GPT-2 для предсказания следующего объекта, без RL.
- **Supervised-контроль** — baseline после ещё 150 шагов обычного обучения.
- **raw_kl001 / raw_kl01 / raw_kl1** — RL по предсказанной доле просмотра с KL-коэффициентом β = 0.01 / 0.1 / 1; чем выше β, тем сильнее ограничено отклонение от baseline.
- **repeat_kl01** — RL с β = 0.1 и штрафом 0.2 за повтор объекта из контекста.

## Выводы

- **RL повысил предсказанное вознаграждение на 8.1%**: с 0.6053 до 0.6544 на test. NDCG@10 основного варианта снизился на 0.51%. Статистически значимого изменения релевантности не обнаружено, но её эквивалентность также не доказана.
- **KL-регуляризация управляет компромиссом:** её усиление уменьшало сдвиг модели и прирост reward.
- **Рост reward не доказывает улучшение пользовательского опыта.** Reward model имеет ограниченную точность и завышает отклик на test; по RMSE она уступает сглаженному среднему по объекту.
- **Greedy-генерация зацикливается:** после RL цепочка из пяти рекомендаций содержала в среднем 1.4 уникального объекта. Sampling уменьшил повторы, а использованный штраф повторов существенного эффекта не дал.
- **Влияние на реальный досмотр и удержание требует отдельной проверки.** RL позволяет управлять поведением рекомендательной модели, однако качество reward model и устойчивость генерации остаются ключевыми ограничениями.
